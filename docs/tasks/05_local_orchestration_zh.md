## 在训练主机上启动控制台

**1. 每次打开新终端时，先进入含有 `main.py` 的目录。** 本机的入口在 `deeprl_signal_control/cbwce_standalone`。如果报错路径以 `deeprl_signal_control/main.py` 结尾，先执行下面的 `cd`。使用训练环境的 Python，并设置正式运行所用的 `CBWCE_RUNTIME_LOCK`、数据与缓存目录。

~~~bash
cd "$HOME/Journal/deeprl_signal_control/cbwce_standalone"
export CBWCE_PYTHON="${CBWCE_PYTHON:-python3}"
export CBWCE_FLOW="$HOME/cbwce-workflows/experiment-02"
~~~

**2. 首次创建工作流时，执行一次初始化。** 选择项目外尚未创建的目录。示例中 Grid 和 Monaco 的正式验证设计种子分别为 73001 和 73002，开发设计使用 9001。初始化会冻结清单。若已有 `$CBWCE_FLOW/workflow.json`，直接到第 3 步。

~~~bash
"$CBWCE_PYTHON" main.py local init-workflow --workflow "$CBWCE_FLOW" \
  --design-seed-grid 73001 --design-seed-monaco 73002
~~~

**3. 启动控制台。** 本机的存储进度页使用 8765，下面的训练控制台示例使用 8766。如果该工作流的控制台已启动，直接打开其地址即可。 以后重启服务时，使用原训练环境和同一工作流目录，执行第 1、3 步。需要在退出 SSH 后继续自动派发任务时，可在训练主机的 `tmux` 会话中运行控制台。

~~~bash
"$CBWCE_PYTHON" main.py local dashboard --workflow "$CBWCE_FLOW" --port 8766
~~~

看到终端打印的地址后，可在训练主机的浏览器打开 [控制台](http://127.0.0.1:8766)。首次进入为手动模式，页面提供 24 个候选的任务表。点击 **Run automatically** 从清点参数开始执行完整流程。正式验证需要已锁定的运行环境和完整的扩展验证。

## 从另一台电脑访问

保持训练主机上的控制台运行。在**自己的电脑**上打开终端，运行下面的 SSH 转发命令。示例使用本机的账号和主机名；如果你平时用 IP 或 SSH 别名登录，把最后一项换成平时的登录目标。远端 SSH 服务需允许 TCP 端口转发。

~~~bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:8766:127.0.0.1:8766 sdc_joran@sdc-1000060-2110363
~~~

保持这个终端打开，在**自己电脑的浏览器**访问 [控制台](http://127.0.0.1:8766)，即可查看曲线、暂停或恢复任务。下次访问时，只要训练主机上的服务仍在运行，重新连接隧道即可。控制台会核对请求端口；如需改用其他空闲端口，请同步更改 dashboard 命令、SSH 转发两端和浏览器地址中的端口。

## 任务阶段

|阶段|任务与依赖|交付|
|---|---|---|
|Inventory / Tuning|核实两地图 × 三算法的逐路口维度、动作与参数量，再训练 24 个候选，每个 1,000 回合|inventory.json、开发验证分数|
|Freeze / Verify|各组合选四个候选中的最佳；在独立源码副本中安装六份胜者 INI，运行完整验证|selection、frozen、gate.json；按已有规则回收候选 checkpoint|
|Baseline 01–06|配置验证通过后，最多六个父任务就绪|每个父控制器的 best|
|WCE 07–12；续训 13–30|每个合格父模型独立释放 1 个离线 WCE 和 3 个续训（Baseline、RG、DR）|最多 24 个第一层子任务|
|Fixed 31–36；Online 37–42|每个合格 WCE 再释放两个续训，均读取匹配的父模型和 WCE|最多 12 个第二层子任务|
|Evaluate / Report|每个续训分支结束后可测试截至停止的 best。30 × 23 个场景任务，各运行 10 个配对实现|阶段内结果随时查看，完整 6,900 次主测试生成正式报告|

## 排队与资源

调参共有 24 个候选。工作流按候选序号交错两张地图与三种算法，首次即可放行 12 个任务，每个任务占一个 CPU 槽位，计算库使用单线程。条件充足时同时运行 12 个，任一任务结束即补下一个候选。每个槽位是调度预算，实际 CPU 利用率会随仿真、验证和写盘而变化。

正式阶段共享最多 24 个工作槽位。本机可用 20 核，默认给正式任务分配 16 核。有 24 个单核子任务同时就绪且内存、磁盘充足时，16 个运行、8 个排队。每个 Baseline 完成即释放自己的 WCE 和 3 种直接续训。每个 WCE 完成再释放 Fixed、Online 两种续训。每个续训完成即释放其评估。

调度器每 5 秒检查可运行任务。当前放不下的大作业留在队列，后续能放下的任务先运行。每个作业首次按 2 GiB RSS 和 1 GiB checkpoint 写入空间估算，以整进程树实测峰值向上修正。内存按 RSS 的 1.3 倍预留，并为系统保留 20% 内存、10 GiB 磁盘。DQL 满 replay 的资源测量与其他任务同时进行。

## 网页操作与恢复

- **Run stage / Run selected** 切换到手动模式，只放行当前选中的阶段／任务。切换授权不会打断已经运行的作业。选择 **Development tuning → Run stage** 会同时授权参数清点、调参后的胜者配置冻结与核验。网页主流程直接显示调参、Baseline、Offline WCE、五种续训和评估；配置检查与最终报告可展开查看。等待依赖的任务在上游通过后才启动。
- **Pause all / Pause selected** 暂停派发；训练在完整回合边界保存，评估保留已完成实现。暂停期间若正在验证，会先完成当前验证。Inventory、Freeze、Verify 和 Report 是完整步骤，已启动的步骤完成后暂停下一步。
- **Resume queue** 解除全局暂停，**Resume selected** 解除所选作业暂停。**Run automatically** 放行所有阶段；单独暂停的作业仍由 Resume selected 放行。**Retry failed** 重试失败项，阶段故障使用对应的 Retry phase。上游要求人工复核时保留原状态。
- 单击任务可查看依赖、最近验证回合、验证曲线、日志和结果。训练显示当前回合／上限，评估显示已完成的实现数。实际停止回合可能早于上限。完整配对报告写入工作流的 report 目录。
- 关闭浏览器不会中断调度。重启网页服务时使用**同一目录和解释器**重跑 dashboard 命令。活动阶段进程与 worker 独立于浏览器；恢复时校验身份、进程和退出回执。若希望关闭服务期间也能自动跨越阶段，保持 dashboard 命令运行在终端复用器或系统服务中。

## 实时曲线

单击任务打开曲线，网页每 5 秒刷新。两个训练观测共用“平均排队车辆数”这一物理量：每个 600 秒需求块结束后更新当前回合的块均值，每个完整回合再保存一个均值。验证点取完整 6600 秒平均排队，空心圈标出历史 best。控制器选最低值，离线 WCE 选最高值。第 0 回合先验证，以后每 100 个完整回合验证一次；每次只用固定实现 0。训练和验证的需求条件可能不同。

Reward 面板默认显示进入优化器前的归一化、裁剪后即时奖励，可切换原始环境奖励。控制器对每个五秒控制步、每个路口等权平均；MA2C 计入邻居，PPO/DQL 使用全网奖励。离线 WCE 对 11 个块的奖励等权平均，原始奖励即块平均排队。Online WCE 分支分别显示控制器和对手的训练奖励，正式验证只评控制器；Fixed WCE 分支只展示控制器奖励。验证 reward 使用同一奖励变换，验证期间权重冻结。

推荐日常观察块平均排队和固定验证曲线。车辆数反映拥堵程度，已完成行程的平均等待秒数使用最终测试的 TripInfo 另行报告，并同时看完成车辆数。每秒样本在线累计，常规日志只增加每回合／验证的奖励摘要；训练恢复时曲线按最近有效恢复点衔接。
