## 1. 目标与实验矩阵

建立 `cbwce_standalone` 独立精简项目，在本地工作站运行。保留 MA2C、DQL、PPO，使用验证选模、平台停止、精简输出及可恢复的本地任务。用户所说的“本地多线程”在本计划中落实为多核并行：优先以多个独立进程运行不同实验，每个进程内部限制计算线程；单训练任务的线程数作为资源试验项。暂不要求 Slurm、集群账户或 Apptainer 镜像。

| 项目 | 协议 |
|---|---|
| 地图 | 5×5 Grid、当前修订入口使用的 Monaco 子路网；不混入修复版地图 |
| 正式种子 | 默认101一个；开发种子9001。后续用新campaign显式扩展 |
| 训练回合 | 6600 秒，1320 个全路网联合控制步 |

## 3. 控制器与参数

IA2C 从新矩阵移除；MA2C 保留邻居观测、fingerprint、邻域奖励和 LSTM。开启有效样本 advantage normalization，排除 padding；邻居奖励权重从配置读取，默认 0.9。检查 entropy 梯度、策略梯度、value loss 的有效系数、奖励裁剪和梯度裁剪。奖励只在 learner 边界缩放一次。保留 n-step return，不同时引入 GAE；MA2C 每 rollout 更新一次。

DQL 替换线性 `iqll`，每路口独立 `wave 128 → LSTM 64 → Q`；独立 online／target 网络，均匀 replay、Huber loss、epsilon-greedy，验证使用 greedy。不加入 Double DQN、Dueling 或 prioritized replay。

| 参数 | MA2C | PPO | DQL |
|---|---:|---:|---:|
| 学习率 | 5e-4 | 3e-4 | 1e-4 |
| gamma | 0.99 | 0.99 | 0.99 |
| 优化器 | RMSProp | Adam | Adam |
| LSTM | 64 | 64 | 64（16 步窗口） |
| Advantage normalization | 开 | 开 | 不适用 |
| 连续 rollout 长度 | 120 个联合控制步 | 120 个联合控制步 | 不适用，逐步写入 replay |
| 每路口一次优化的数据量 | 当前 rollout 的 120 个有效样本；末段可更短 | 同一 rollout 的 120 个有效样本；末段可更短 | replay 随机抽取 64 个转移终点，各带最多 16 步历史 |
| 更新 | 每 rollout 一次 | 同一 rollout 四轮，当前实现每轮使用整个有效序列 | warm-up 后，每 4 个联合控制步、每路口优化一次 |
| Entropy | 0.01 | 0.01 | 不适用 |
| PPO clip | — | 0.2 | — |
| Replay | — | — | 50,000 联合转移 |
| Warm-up | — | — | 5000 步 |
| Target 同步 | — | — | 每 1000 学习步 |
| 梯度范数上限 | 40 | 40 | 10 |

保留现有 MA2C／PPO 编码宽度。DQL 初始 epsilon 在 500,000 步内从 1.0 线性降至 0.01。

### 3.1 哪些参数需要一致

**不强制统一 rollout／batch、更新频率或梯度裁剪阈值。** 表中 `120 / 120 / 64` 与 `40 / 40 / 10` 保留为开发起点，不能仅因数值不同判定不公平，也不能宣称这些起点已最优。

- MA2C/PPO 的 120 是新采集的连续序列长度，按 5 秒控制间隔对应 600 秒；DQL 的 64 是历史 replay 样本数，不表示连续 320 秒，也不表示 64 个回合。MA2C/PPO 的 padding 不计入有效样本。
- MA2C 使用当前 rollout 一次；PPO 的裁剪目标允许对同一批数据做多轮优化，本实现为四轮；DQL 使用 replay 和 target 网络，所以维持另一套更新节奏。这些机制有算法依据，但 `120、64、4` 是本项目的选择，不能冒称来自论文的统一最优配置。[PPO 原论文](https://arxiv.org/abs/1707.06347)、[DQN 原论文](https://deepmind-media.storage.googleapis.com/dqn/DQNNaturePaper.pdf)。
- “学习步”统一指一个 5 秒全路网联合控制步，不乘路口数，也不指优化器更新次数。在 warm-up 结束、完整 1320 步回合中，每路口 MA2C 为 11 次优化，PPO 为 44 次，DQL 为 330 次。DQL 每次抽 64 个转移，约为每个新增步 16 次样本抽取；这是抽取量，不代表每条经验恰好重放 16 次。
- 梯度范数上限是稳定性参数。MA2C/PPO 对每路口 actor 与 critic 的合并梯度裁剪，DQL 对每路口 online Q 网络梯度裁剪；target 网络不做梯度优化。损失、参数量、奖励尺度及优化器不同，相同阈值也不代表相同更新幅度。保留 `40 / 40 / 10`，在开发阶段记录裁剪前范数、梯度裁剪触发比例、裁剪缩放系数和 loss；PPO 的策略 ratio clip fraction 与梯度裁剪比例必须分开报告。异常时先检查尺度与数值稳定性，再决定是否预先登记额外敏感性试验。

公平性统一的是：同一地图的仿真和动作接口、环境交互预算、验证流量与随机实现、调参候选数量及评估规则；同一控制器的五种续训分支必须使用完全相同的网络和优化设置。同时报告每路口／全网参数量、优化次数、wall-clock、总作业 RSS 和验证开销。各分支的停止回合可以不同，同时报告实际交互步数和计算成本；保留现有每地图／算法四个开发候选，不因本次解释自动扩大搜索。

### 3.2 神经网络是否需要相同

DQL 现已参考 PPO／MA2C 的 wave 编码宽度与 LSTM 门控方程。MA2C/PPO 保留独立 actor、critic；DQL 保留独立 online、target Q 网络。

| 控制器 | 每路口当前网络 | 观测与记忆 |
|---|---|---|
| MA2C | wave 128；fingerprint 64；LSTM 64；独立 policy/V 输出 | 含邻居 fingerprint；跨 episode 内步骤传递循环状态 |
| PPO | wave 128；LSTM 64；独立 policy/V 输出 | 无 fingerprint；跨 episode 内步骤传递循环状态 |
| DQL | wave 128；LSTM 64；每动作 Q 值 | 无 fingerprint；最多 16 步历史窗口 |

DQL 均匀抽取 64 个转移终点，从定长 replay 重建各自连续历史，遇 terminal 或最早保留的转移时停止，左侧补零通过 mask 屏蔽。online 与 target 窗口均从零状态开始，与有限窗口推理一致；target 窗口左移并追加 next observation。仅终点计算 Huber TD loss，梯度通过有效历史传播，不另设截断梯度的 burn-in。`sequence_length=16` 是可配置的工程起点，尚非调优结论。完整 checkpoint 保存推理历史和 replay；架构标识拒绝旧版前馈 checkpoint。

可训练 online 参数量与含 target 的存储量分别报告。相同 LSTM 宽度不代表系统完全相同：MA2C 有 fingerprint，DQL 使用有限历史和 replay，MA2C/PPO 传递 episode 内状态。只归因于算法的结论仍需匹配输入与记忆机制的消融。

Grid 与 Monaco 的 MA2C、DQL、PPO 和 WCE 均使用 **仅 wave 的交通观测**。控制器保留本地／邻居 wave，MA2C 保留邻居 fingerprint 通信特征。WCE 仅拼接按节点补齐的 wave：Grid CNN 输入为 25 × 6 = 150 维（6 通道，原为 300 维／12 通道）；Monaco GCN 输入为 28 × 11 = 308 维（每节点补齐到 11 条监测车道）。wave 沿用原采样口径：Grid 为检测区域车辆数，Monaco 为车道车辆数，经 `norm_wave` 归一化和 `clip_wave` 截断。等待时间不作为输入，queue 奖励保持不变。六套控制器 INI 固定 `observation = wave`，移除了无效的 `num_ft`、`norm_wait`、`clip_wait`、`fast_wait_metric` 参数。新的观测签名拒绝旧观测版本 checkpoint；需重新训练并生成配套 WCE checkpoint。

| 奖励除数 | MA2C | PPO | DQL |
|---|---:|---:|---:|
| Grid | 2000 | 3000 | 3000 |
| Monaco | 200 | 1000 | 1000 |

训练裁剪阈值为 2；评估指标不缩放、不裁剪。MA2C 是邻域奖励，其他控制器是全局奖励，不强制使用相同除数。

每地图／算法四个开发候选，各 1000 回合：MA2C 学习率 `{5e-4,2.5e-4}` × entropy `{0.01,0.001}`；PPO `{3e-4,1.5e-4}` × 同样 entropy；DQL `{1e-4,3e-4}` × replay `{50000,20000}`。按开发验证 best 选择，同分优先表中起点。正式种子和最终测试不调参；五种续训共用参数。

## 4. 验证、best 和平台停止

### 4.1 固定 DR 序列与一个实现

初始训练和所有五种续训统一在第 0 回合、每 100 个完整回合及停止时验证；同一终点若刚完成相同验证则复用结果。

| 项目 | 修订后的控制器验证 |
|---|---|
| 每地图需求组数 | 11 个预生成 DR 混合组 |
| 每组持续 | 600 秒，120 个联合控制步 |
| 一次完整 rollout | 11 组按固定顺序依次运行，共 6600 秒／1320 个联合控制步 |
| 常规验证实现数 | 1；每次从空网络开始，运行完整 11 组 |
| 一轮验证的仿真量 | 1 个完整 rollout，共 6600 仿真秒；11 组之间不 reset |
| 网络／循环状态 | 仅在完整 rollout 开头 reset；需求组切换时不清空车辆、排队或 LSTM |
| 停止方式 | 最少回合后，连续 10 次验证无实质改善即停止；不追加确认验证 |

已确认采用 `11×600` 秒；以下公式和预算均按此计算。

需求组不是原始十一种 profile 逐个播放，而是**每个组由这些 profile 混合得到**。默认沿用现有 DR 分布：每地图离线采样 `w_b ~ Dirichlet(1,…,1)`，`b=1,…,11`；每个 `w_b` 有十一项非负权重且和为 1。以归一化原需求生成 `d_b = Σ_k w_bk d_k`，本轮不额外引入总流量倍率、空间噪声或 peak 参数。11 个组是小型固定开发／选模基准，不保证覆盖整个 DR 空间；泛化结论仍由独立最终测试支持。

冻结要求：保存完整十一组权重、组 ID、顺序、起止时间、profile 名称与顺序、地图／需求／生成器哈希、设计种子及一个常规 realization 的随机流身份（由 manifest 哈希、场景 ID、实现索引和流名称确定交通、SUMO 和策略种子）。不同地图的 profile 存储顺序可能不同，权重必须按名称绑定，不能跨地图直接复用未经核对的数组位置。冻结后所有 checkpoint、算法、正式训练种子和续训方法都复用各自地图同一套验证输入，不重新采样权重或变换顺序。开发调参使用同规格、不同组和不同随机流的开发 manifest，不用正式选模集反复调参。

常规验证固定使用索引 0 的一个实现，复用十一组需求率、顺序和固定的到达／车辆随机流、SUMO seed 和 MA2C/PPO 策略 seed；DQL 使用 greedy。交通 artifact 按完整 rollout 生成并共享。车辆可跨需求区间留在网络中，组分数因此包含前序交通影响；11 个区间不能当作 11 个独立实验样本。验证过程不训练 WCE，也不让 WCE 改写该外生 DR 序列。模型与随机流独立，不改变训练参数、优化器、replay 或计数。

### 4.2 指标与平台停止

选模采用一个完整 rollout 的平均全网排队，包含从第 1 秒到第 6600 秒的所有测量：

\[
J_{\mathrm{val}}=\frac1R\sum_{r=1}^{R}\frac1T\sum_{t=1}^{T}\sum_{\ell\in L}q_{\ell,r}(t),\qquad R=1,\quad T=6600.
\]

因十一组各为 600 秒，此分数等价于先算各组 600 秒平均排队再等权平均。常规 best 只使用这一个总分；同时保留每个实现和每个区间的均值作诊断。一个固定实现降低验证成本，但不提供跨随机实现的方差估计；本阶段仅用一个训练种子101，不估计跨训练种子方差；最终每场景仍保留10个评估实现。每 100 个 6600 秒训练回合进行一次常规验证，额外仿真秒数约为训练的 1%；不含 episode 0、停止／确认验证，也不等于实际 wall-clock 开销。

任何严格下降都保存 best；同分保留更早模型。吞吐、pending、teleports、碰撞和尾部指标只诊断，不参与排名。不完整 rollout 无有效分数。

| 阶段 | 最少回合 | 最大回合 |
|---|---:|---:|
| Initial | 1000 | 5000 |
| Offline WCE | 500 | 3000 |
| Continuation | 1000 | 5000 |

停止只需同时满足：达到当前阶段最少回合，且连续 10 次常规验证没有实质改善。每 100 回合验证一次，通常对应 1000 回合；episode 0 只建立基线，不计为一次“无改善”。patience 在达到最少回合前也累计。恢复完整保存无改善次数，不因分段或重启清零。

实质改善阈值为 `max(anchor×0.01,0.1)`。控制器分数下降、WCE 分数上升达到阈值时，更新 anchor 并将无改善次数清零；微小改善累计达到阈值也算实质改善。任何严格改善仍保存 best，同分保留更早模型；微小改善不重置 patience。

不再要求最近分数极差小、拟合斜率小、当前接近历史 best，也不再追加九次／二十次确认验证。极差、斜率、当前与 best 的差值继续作为诊断记录；entropy、loss 和梯度指标沿用训练日志，不作为停止门槛。停止后选用历史 best，不用最后一轮较差的模型。各方法采用相同的阶段上限，实际停止回合可以不同。

达到 patience 条件记为 `early_stopped`；父模型／离线 WCE 若始终没有实质改善，也允许停止，但记为 `no_learning`。先达到最大预算时记为 `max_budget_reached`，父模型／离线 WCE 无实质改善时仍记为 `no_learning`。异常为 `failed`，分段未完成为 `interrupted`。提前停止不等于证明收敛或达到全局最优。正式下游沿用历史 best，仅自动放行 `early_stopped` 上游；`no_learning` 和预算耗尽需检查。

### WCE

冻结 best 父模型。Grid 保留 CNN-A2C，Monaco 保留 GCN-A2C；每 600 秒输出十一维需求权重，每完整回合更新一次。第 0 回合及每 100 个完整回合各用一个固定实现（索引 0）验证完整 6600 秒平均排队，越高越好；不追加确认验证；达到该阶段最少回合且连续 10 次无实质改善即停止。

这里验证的是 WCE 自己生成的对抗需求策略，**不能用固定十一组 DR 序列替代其动作**，否则不能区分 WCE 候选。控制器与离线 WCE 的常规验证各使用 1 个固定实现，取消补充确认，同样使用 patience 停止。在线 WCE 分支的 controller best／停止仍依赖上述外生固定 DR 序列。

固定的是外生随机流与需求约束，不是 WCE 自身生成的完整交通轨迹。随机流按区间、OD 和随机量类型索引。保留原学习率、奖励尺度、entropy；WCE advantage normalization 默认开启（`adv_norm = true`）：每次更新在完整 11 个宏步样本内使用 `(A − mean(A)) / (std(A) + 1e-8)`，标准差采用总体标准差；仅处理 actor advantage，critic return 与奖励缩放保持原定义。离线 WCE 和 online WCE 均生效，fixed WCE 仅推理。日志记录标准化前后 advantage 均值及标准差。父模型通过哈希引用，不重复复制。正式 fixed／online 只使用已按 patience 停止的同一 best WCE。

### 续训与公平性

五种方法同父模型分叉；random group 均匀抽独热组，DR 使用 `Dirichlet(1,…,1)`，fixed 冻结 WCE，online 每回合更新 WCE。DQL 保留 replay／target／优化器，但分叉时 epsilon 从 0.1 在 132,000 步内降至 0.01；恢复不能重置。

父模型作为续训 episode 0 的 best 候选；允许续训未改善。新增 1000 回合是允许早停的下限。训练结束后冻结整个验证历史中的 best，同分保留较早的 checkpoint。Online 停止仅看外生验证，不看变化对手的训练 reward。完整恢复点保存同一时刻 controller 与 WCE，不能拼接不同时刻的各自 best。

## 5. 内存和数据减量

每秒仍测量队列。使用 float64 在线累加器计算和、平方和、峰值、车辆计数与时间完整性；保留当前车道向量和最长 600 秒全网队列环形缓冲。WCE 直接累积区间均值。episode 一条摘要，学习诊断按需求区间聚合。`batch_lengths` 改为直方图；只在测试保留完整序列。

DQL replay 用定长 NumPy 数组，容量按联合转移计。观测／reward float32，action 整数，terminal bool；不存不用的 policy/value 数据。分块序列化，避免完整缓冲深拷贝；禁止 float16 或有损压缩。

验证采用 inference-only 图，不创建优化器和 replay，DQL 只加载 online 网络。训练暂停期间在独立进程顺序验证；冻结父控制器同样使用推理模式。

| 输出模式 | 数据 |
|---|---|
| 正式训练 | episode 摘要、区间诊断、需求权重与哈希、验证历史 |
| 常规验证 | rollout 标量、场景分数、候选身份 |
| 最终评估 | 标量、每分钟曲线、预定义窗口的车道统计 |
| 审计 | 逐秒车道、控制记录和必要 SUMO 数据 |

训练默认关闭每回合 NPZ、逐秒 JSONL、每步奖励、每 agent 每更新梯度日志、自动图表和不必要 tripinfo。完整审计限集成检查及最终模型 Uniform／peak_1.5 第一条实现。需要 tripinfo 时在本地临时盘流式解析成摘要再删除 XML；失败保留有限日志尾部。

训练交通每 600 秒即时生成，只保存生成状态、权重、版本及哈希。固定评估交通按需生成一次并压缩共享，车辆引用 route table，避免重复边序列。种子必须配套生成器、地图、需求和交通哈希。评估写压缩分片；CSV、图和 TensorBoard 离线生成，不重复保存等价原始数据。不同软件版本不保证逐位一致。

## 6. Checkpoint 与归档

完整 checkpoint 含参数、优化器、replay／pending、RNG、调度、计数、验证状态和在线 WCE；轻量 snapshot 只有推理参数及身份，不能恢复训练。

每十回合保存恢复点，保留最新两个；当前 best 保留完整状态；最近五验证候选保留轻量快照；当前 best 另保留推理快照；最终保留完整状态；下游引用的父模型与 WCE 固定保留。角色相同复用文件；仅清理无引用且有有效替代的中间产物。持续保存 best 不代表永久保存所有曾经的 best replay。

写临时目录→状态与参数→哈希→完成 manifest→目标端校验→更新引用→清理。跨文件系统先复制目标临时目录，再在目标文件系统原子发布。失败不得删除上一有效恢复点。清理范围只包含新项目托管数据。

## 7. 本地多核并行执行

### 7.1 当前执行范围

本阶段使用本地 Linux 工作站和 CPU，完成开发调参、父模型、离线 WCE、续训和评估。Hábrók 部署暂缓；现有 `scripts/slurm/` 与 Apptainer 定义作为以后迁移的可选材料保留，不作为本次运行前置条件。正式实验矩阵、训练预算、验证规则和随机种子沿用前文，不因改为本地而减少科学比较要求。

并行的基本单位是一个“地图 × 控制器 × 训练种子 × 阶段／续训方法”任务。不同任务使用独立 Python 进程、TensorFlow session、SUMO 实例、随机流和输出目录。单次训练仍按原有顺序采样和更新；本轮不引入共享 replay、异步梯度或分布式 learner。

### 7.2 进程与线程配置

| 项目 | 本地起点与调整规则 |
|---|---|
| 同时活跃的训练任务 | 先运行 1 个任务测量，再测试 2 个；资源允许时比较 4 个，不直接启动全部实验 |
| 每任务 TF intra-op／inter-op | 初始均为 1；单任务资源试验可比较 intra-op 为 2，inter-op 保持 1 |
| BLAS／OpenMP／MKL | 初始均为 1，避免每个实验再开一整套核心线程 |
| GPU | 继续关闭，沿用当前 CPU 实现 |
| 验证 | 该任务暂停学习，以独立推理进程顺序验证；训练进程仍驻留内存 |
| 最终测试 | 按独立模型／评估批次并行，纳入同一个本地资源调度上限 |
| 作业时长 | 不再强制 24 小时分段；可持续运行，也可按用户设置的本地分段时长退出后恢复 |

启动线程环境变量的起点如下，必须在导入 TensorFlow／NumPy 前生效：

```bash
export OMP_NUM_THREADS=1
export OPENBLAS_NUM_THREADS=1
export MKL_NUM_THREADS=1
export TF_NUM_INTRAOP_THREADS=1
export TF_NUM_INTEROP_THREADS=1
export TF_ENABLE_ONEDNN_OPTS=0
```

有效TensorFlow session线程现由统一入口读取，显式TF线程环境变量优先于INI回退值，并记录在runtime身份中；改变线程后需重新验收。DQL、MA2C/PPO和WCE现共用有效线程配置入口，默认1；线程变化需重新锁定环境与验收。不同并行度下首先核对动作、奖励、更新次数与恢复一致性，再比较速度；调整线程或数值设置后重新验证运行环境。

### 7.3 按整任务资源决定并发数

分别测量两地图 × 三控制器，至少覆盖父训练、在线 WCE、验证期间和 checkpoint 写出期间。DQL 需包含 replay 填满后的情况。记录整个进程树（训练 + 验证 worker + SUMO）的峰值内存、CPU 利用、episode 时长、checkpoint 写出耗时、磁盘字节数及文件数，不能仅用 trainer 的 `ru_maxrss` 代表总需求。

设可用于实验的内存预算为 `B_ram`，先为操作系统和其他本地程序预留至少约 20% 总内存；任务 i 的实测整进程树峰值为 `M_i`。调度器只在 `Σ(1.3 × M_i) ≤ B_ram` 时启动对应任务，并同时检查 CPU 和磁盘空间预算。没有测量值的组合先单任务试跑，不能把以前的 8 GiB Slurm 申请或短流程 RSS 当作正式需求。

CPU 预算按可用物理核心及实测任务占用制定，给桌面操作和系统保留余量；不能将“任务数 × TF 线程数”视为全部 CPU 开销，因为 SUMO 也占用 CPU。比较 1、2、4 个并发任务时，主要看总完成回合数／小时、单任务耗时和内存／磁盘压力。若总吞吐不再提高、频繁交换内存或写盘成为瓶颈，则降低并发数。训练与最终评估不能各自独立启动一批任务而绕过总上限。

### 7.4 本地任务编排和恢复

本地批量调度入口`main.py local prepare/run/status/resume`已实现，复用现有 `main.py parent/wce/continue` 子进程接口。任务清单记录 run ID、argv、父 checkpoint 哈希、输出目录、有效线程配置、资源估计、状态、退出码及错误日志位置。调度器需具有总并发上限、任务依赖检查、持久队列状态、停止信号转发和重复任务保护；恢复时先核对仍活跃的任务，不能重复提交同一运行目录。

阶段依赖为：父模型按 patience 停止后才放行离线 WCE 与相应续训；fixed／online 还需共享离线 WCE 已按 patience 停止。不同地图／算法／种子可以交错调度，不必等待整个大批次一起结束。下游同时检查本地子进程成功退出、完整 checkpoint 校验及应用状态 `early_stopped`，不再依赖 `sacct` 或 Slurm 回执。`max_budget_reached`、`no_learning` 和 `failed` 必须明确报告，不能自动当作已通过上游门禁。

完整 checkpoint 仍每十个完整回合保存，并在验证、best 更新及阶段结束时按原规则持久化。用户停止或本地分段结束时，尽可能停在完整回合边界；未完成回合丢弃并从最近有效恢复点重跑。恢复不重置预算、patience、随机流或 DQL 续训探索日程。当前 CLI 的 `--segment-seconds` 默认仍为 23 小时；本地入口默认显式传0以禁用分段，也支持设置分段时长与自动续跑，不能误把正常分段退出当作任务完成。异常退出先记录与检查原因，避免无限自动重试。

### 7.5 本地环境锁和正式运行门禁

采用本地独立 Python 3.10 环境（venv 或 Conda），沿用 TensorFlow CPU 2.15.1、NumPy 1.26.4、SUMO／TraCI／sumolib 1.26.0 基线及哈希依赖锁。记录精确 Python 补丁版本、依赖清单、SUMO 二进制版本与 SHA-256、操作系统、CPU、有效线程配置和科学源码／输入哈希。任务运行中不临时升级依赖。

已新增显式的 `local` 运行环境锁及`main.py runtime-lock`生成／验证流程，让正式任务验证本地环境身份与本机生成的完整 gate，而不是要求 SIF 哈希。保留“冻结 validation manifest、正确协议版本、已验证代码／输入、完整父状态”的门禁；不能通过使用 `--pilot`、伪造镜像锁或跳过预检来运行正式实验。

`experiments/runtime.py`支持本地／容器两种锁；本地任务不依赖Slurm，历史Slurm入口保留自己的作业检查。正式放行要求当前锁定环境通过`verify.py --extended`及两地图×三算法检查；开发系统的正确性证据不等于正式环境验收。
